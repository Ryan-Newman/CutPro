# Agent.md — read this first (any model)

Goal: continue work on **CutPro** without re-discovering the project. This file + the `## Log` tail of `PROGRESS.md` should be all the context you need before touching code. Keep this file short; update the **Handoff** section at the end of every session.

## What this is
Premiere Pro–style video editor, **native Windows desktop** (WPF, .NET 9, C#). Not a web app — the user rejected the web version. One NuGet package: `Microsoft.ML.OnnxRuntime.DirectML` (AI object selection + content analysis; MobileSAM, Whisper base and CLIP B/32 are downloaded on first use, with consent, to `%LOCALAPPDATA%\CutPro\Models`, never shipped). Ask before adding others. **ffmpeg + ffprobe ≥ 7 are required** (winget `Gyan.FFmpeg`, 9.0.2) for import, preview, audio and export.

## Design rules (don't break)
- Undo = JSON snapshot of `Clips` only. Mutate inside `ed.Edit(() => …)`; drags use `Checkpoint()`/`Commit()`; inspector uses `Touch()`.
- All edit times go through `Editor.Frame()` (frame-accurate).
- Linked clips share `LinkId`; a cut gives the right-hand pieces a fresh shared LinkId. Video clips with a linked audio clip have `NoAudio = true` (export/preview must not double the sound).
- Preview and export share `Editor.Fit` / `Editor.Placement` → WYSIWYG. Change both together. Media `Width/Height` are *display* dims (rotation applied); ffmpeg auto-rotates on decode.
- Titles are drawn ONLY by `TitleVisual` (preview = live element, export = its PNG via `PrepareExport` on the UI thread before the background export). Don't reintroduce ffmpeg drawtext. Text masks: preview = OpacityMask on the nested per-track canvases (`Preview.below[k]`, brush with **absolute** viewport); export = matte PNG → alphamerge over black; fades/opacity blend the mask: alpha = m + (1−f)(1−m).
- Gaussian blur: preview `BlurEffect(radius)`; export `gbrap → transparent pad → gblur(sigma = Exporter.BlurSigma(r) = 0.37r + 0.9) → unpremultiply` (measured vs WPF; straight-alpha blur darkened edges).
- Playback = audio-master clock + ffmpeg-decoded frames. Do NOT go back to WPF MediaElement/MediaPlayer (drift, slow seeks, choppy after cuts, no MKV/HEVC).
- Per-frame code (`Preview.Sync`, `OnRendering`) must not touch the disk (`Offline` is cached; scrub-cache reads are the one exception, ~30 KB), start processes on the UI thread, or allocate frame-sized buffers (use `FramePool`). Never draw a decoder's frames into a layer whose clip is a different file/size. Use the high-resolution ms clock in Preview (TickCount is 16 ms coarse).
- Hardware decode is chosen per file by measurement, never assumed: on the dev PC (RTX 4090 + 7800X3D) GPU wins 4K playback throughput, but CPU (default frame threads) starts fastest for ≤1080p and slice threads can beat the GPU to the first 4K frame. `-hwaccel_output_format cuda` (CudaScale) breaks with rotated video → not a candidate then.
- Shortcuts mirror Premiere defaults (S = snap toggle, Ctrl+K = add edit, Q/W, C/V, ;/').
- **Themes = flat (Dark/Light/Colorful) or material (Frosted Glass/Stone/Metals/Nature).** Panels are `Card`s with surfaces `B.Surf.<Region>`; structural lines use `B.Divider` (transparent in material themes), header strips `B.Strip`, inspector headings `B.Heading`. A material theme lists its light-surface regions (`LightCards`) — those cards get the `OnLight` ink as **local resources**, so code inside a card must resolve brushes through the element (`ThemeManager.Brush(this, key)` / `SetResourceReference`), never the global `ThemeManager.Brush(key)` (the timeline on platinum would get light text). Card palettes are applied before panels redraw (`ApplyCards` first in the `Changed` handler). Never put an `Effect` on a card (re-renders the live video every frame) — `Card` draws its shadow.
- UI colours: only `{DynamicResource B.<key>}` (XAML) / `SetResourceReference` / `ThemeManager.Brush(key)` (code) — never hard-coded hex (except video content, clip label text). Custom-drawn controls re-read brushes on `ThemeManager.Changed` (see `TimelineView.ReloadTheme`). New keys must be added to all 3 palettes. Subclassed controls need `SetResourceReference(StyleProperty, typeof(Base))` (implicit styles match the exact type only).
- Object masks: outlines are normalised to the media frame and keyed by **source** frame (30 fps, `Editor.SourceFrame`), so cuts/moves keep them; cut pieces share the mask Id + `MaskTrack` (settings independent). Tracks live in `Editor.MaskTracks`/`ProjectFile.MaskTracks`, outside undo. Preview (`MaskFx`) and export (`MaskExport` + Exporter mask block) must change together — `--objtest` compares them. Mask videos: timestamps are rebased (`settb=1/30,setpts=N`, clip `fps=30`) because mkv stores ms and k/30 rounds (1 in 3 frames used the previous mask).
- Mask keyframes: `MaskTrack.Keys` are never overwritten by tracking; trackers get a snapshot of the keys (`TrackAsync(..., keys)`) and re-anchor on them (AI: prev outline/box, low-res mask reset; shapes: new template). Stored polygon arrays are immutable — edits store new arrays (undo snapshots share them). Undo: `Editor.Hist` = clips JSON *or* one mask's `MaskTrack.State`; single changes via `MaskEdit`, drags / tracking runs via `MaskBegin`…`MaskEnd`; undo while tracking cancels the run and undoes it (`HistoryMoving`).
- Clip keyframes: stored in `Clip.Anim` (inside the Clips undo snapshot), keyed by SOURCE time (survive trims/cuts). Every consumer calls `Anim.Value` — never read `c.Scale`/`c.X`/… directly for rendering. Animated or rotated video/image clips export through `LayerPlan` (sendcmd per frame; `rotate c=black@0` — `c=none` leaves garbage; canvas must be packed RGBA with `overlay=format=rgb` — `gbrp` mode drops alpha) and snap to whole pixels in the preview (`Placement`) because ffmpeg places on whole pixels. Animated titles render per frame through `TitleVisual` into FFV1 bgra (`settb=1/30,setpts=N` on input). Parity: titles 42–50 dB, image layers 23–40 dB on the 1 px grid test pattern (resampling), no placement shift.

- **Theme animations** must not cost playback: anything moving in several places at once makes WPF merge dirty regions and repaint the whole window each frame. Creatures hold still while playing / scrubbing / dragging (`Ambience.Playing`); vector art that moves is baked to bitmaps or `BitmapCache`d; new effects get measured with `CUTPRO_THEME` + `--playtest` (UI frame gap ≈ the Dark theme's).
- **Audio mix:** `Mixer.Mix` is the only mixer — playback (`AudioOut`), meters and loudness (`Mixer.Render` / `Measure`) all run it; `Exporter` builds the same math in ffmpeg (clip volume / fades / crossfades, then `pan` = track fader × balance per clip, `amix` sum, master `volume`). Positions are whole 48 kHz samples on both sides (`aformat` first, `atrim start_sample`, `adelay …S`) — NTSC frame times fall between samples. Change both together; `--audiotest` compares them sample by sample (≥ 50 dB, no shift). Mute = `TrackOff`, solo = `MixState` (instant toggles, not undoable); fader / pan / master are undoable (`MixBegin`/`MixEnd`/`MixTouch`, `Hist.Mix`). Loudness normalization measures in-app (`Loudness.Meter` = ffmpeg ebur128 within 0.05 LU), then exports one gain (+ `alimiter` at 4× rate only when the true peak would pass the ceiling). Meters only redraw while the mixer is showing and something changed (measured: no playback cost). **Track automation:** fader (dB) and balance keys per track (`TrackMix.GainKeys` / `PanKeys`, timeline time, in the mixer undo snapshot) → `Mixer.AutoTable`: L / R gains per 240-sample block counted from timeline sample 0 (value at the block start); sources on the track carry the tables (`Src.AL/AR`) instead of `GL/GR`; the export sums the track's clips (amix) and applies the SAME tables per side (asetnsamples 240 → channelsplit → asendcmd + volume just before each block → join) — `--audiotest` 83 dB. Recording = `AutoRecorder` (touch: overwrite from grab to release, keys every change / 0.5 s, later keys continue); paused moves on an automated control key the playhead. **Master automation:** `MixState.MasterKeys` (dB) → `Mixer.MasterOf` = `MasterMix` (gain, or a table per 240-sample block; a float converts to it — pass `MasterOf`, not `MasterGain`, wherever the mix is rendered) applied after the sum; export: the same table × the normalization gain via asendcmd + volume@mst before the limiter — `--audiotest` 79.6 dB. **Submixes:** `MixState.Subs` (≤ `Mixer.MaxSubs` = 4: fader, pan, mute, automation, effects) and `TrackMix.Output` (−1 = master); sources of a routed track carry a `Mixer.SubBus` — `Mixer.Mix` sums those tracks' post-fader buses into the submix buffer, runs its chain (also in silence: tails; warm-up after a jump = the routed tracks' own mix via `Mixer.SubInput`, i.e. `Render` of those sources with `Sub = null`), applies its gains / tables into the mix (meters at `SubSlot`). Export: `AudioDsp.EnsureSubFile` renders exactly that (the routed tracks through `Mixer.Render` + the chain) to f32le; the exporter skips routed tracks' clips and reads the file → `pan` or the automation block — `--audiotest` 84.7 dB.
- **Speed / reverse / hold / time remapping:** `TimeMap.Src` is the one map from timeline time to source time — preview, export, masks (`Editor.SourceFrame`), keyframes (`Anim.SrcTime`), waveforms, transitions (`Extended`), edits (razor / trim: new In = `Src` at the new start). `Clip.In` = the source time shown at the clip's start (reversed: the high end), so 100 % forward clips are unchanged. Remapped video never decodes "live" for the export: `Remap` renders the clip's range (handles included) frame by frame from `TimeMap.NativeIndex` (native grid: `fps=<native>` after a seek 0.1 ms before the frame) into a lossless file that the preview plays too, so they match frame for frame (`--speedtest` reads every frame back). Until it is rendered the preview decodes the media on the same native grid (forwards / held) or shows the scrub cache (reversed, while playing). Remapped sound = `AudioCache.EnsureDerived` (atrim → pad → areverse → atempo / asetrate), read by the mixer and by the export. **Pitch shift** (`Clip.Pitch` semitones, `Clip.Formant`) is derived sound too (`AudioCache.Derives`): ffmpeg `rubberband=pitch=…:formant=…` keeps the length but moves the sound by a ratio-dependent amount (−13 ms at +7, +16 ms at −7), so `Conform` measures it once per setting on a click (`PitchLag`, energy centre) and shifts the rendered file back (`Unshift`) — `--audiotest`: in sync within ~1 ms, export = mixer exactly. Speed keyframes are keyed by SOURCE time (they stick to the content, like every key), integrated in `TimeMap.Ramp`; no formulas on Speed; ramps change the picture only (Premiere), the clip keeps its length.
- **Stabilization** (`Clip.Stab`, any video clip — speed changes too): rendered like Remap and in Remap's file layout (frame k = the stabilized native frame `Remap.Frames` picks for output frame k of the clip's range, sequence rate, lossless) — the preview plays the file once ready (the plain clip meanwhile; no scrub-cache proxy while it plays the file — proxies aren't stabilized), the export merges `Stab.PrepareExport` into its remap inputs, so they show the same frames (`--stabtest` 45–48 dB, no shift). vid.stab: detect and transform on Remap's native grid (`fps=<native>` after a seek just before the first frame), ffmpeg run in the cache folder with a bare .trf name; `optalgo=gauss` (the default global optimizer flattened slow pans: 2.1 → 0.4 px/frame) except tripod mode. When `Remap.Frames` is out of order (reverse), pass 2 writes the stabilized native frames in order to a lossless segment on the native grid and `Remap.Render` picks the frames from it as from media; `Remap.PrepareExport` skips stabilized clips (Stab renders them, `Stab.Spec` includes `Remap.Spec`). Each razor piece renders on its own (its range); object masks / frame grabs still read the unstabilized media.
- **Colour:** one `ColorGrade` → one 33³ LUT (`Grade.For`). Preview: the LUT on a copy of each decoded frame (`GradeBuf`) and on scrub-cache frames, in C# with lut3d's own arithmetic (float coordinates v·(N−1)/255, truncated output); export: `lut3d=file=<bare name in %TEMP%>:interp=tetrahedral` after scale. Vignette: preview = `RadialGradientBrush` (`MaskFx`), export = the same brush rendered to PNG (STA thread) overlaid with `overlay=format=rgb`. Change both sides together; `--colortest` compares them (LUT within 1/255, frames ≥ 34 dB). Never read a .cube or any file per frame (the signature is the grade JSON).
- **Drawn looks (cartoon / cel / anime):** `Toon.Graph` runs in the preview's decoder (`FrameStream` `Vf` → `Decoders.Filter` extra, after scale, before pad) and in the export chain after scale; pictures go through ffmpeg too (`Preview.ToonStill`). Every filter is spatial, so a frame looks the same wherever decoding starts. The scrub cache can't show a look (proxy off when `Vf` ≠ ""). Look decoders need ~2× the time to the first frame and catch up at ~13 ms/frame: separate start-up estimate (`startupVfMs`), and while paused within 1 s of a cut into a clip with a look its decoder starts early (`atRest` pre-roll); `Continues` only hands over between pieces with the same `Vf`. Measured by the `looks` playtest (0 frames > 1 off, no freezes).
- **Scopes** must not cost playback: half-size capture into one reused `RenderTargetBitmap` + buffer (a new bitmap per update grew the working set ~200 MB), compute off the UI thread, throttled, only while the Scopes view shows.
- **Thumbnails / intros:** `ThumbRender.Draw` is the only renderer (canvas and saved file). An intro is one `ed.Edit` (Clips undo) built from copies of the timeline (titles left out); everything after it moves later by exactly its length; one clip per track at a time (title V2, subtitle V3, stills on V1).
- **Blend modes:** one formula per mode on 8-bit values (t = clip, b = below; results rounded to integers) in `Blend` — the export's lut2 expression and the preview's HLSL are written from it and `--compositetest` checks all 65 536 pairs (lut2 exact, shader ≤ 1). Preview: the clip's layer sits in a frame-sized, ClipToBounds host on its track whose `BlendEffect` samples a `VisualBrush` of `Preview.below[k]` (absolute viewbox = the frame; V1 blends with black); the shader un-premultiplies the clip and outputs premultiplied `B·α, α`, so the host's opacity and anything under it compose like the export. Idle hosts collapse (`SyncBlendHosts`). Export (`BlendInto`): the clip (kept RGB, no 4:2:0) on a transparent frame canvas → un-premultiply → lut2 with the composite's frames k0…k1 → alphamerge → overlay on them → led by `tpad` transparent frames up to k0 and overlaid back with `enable` on those frames only. Never re-attach a trimmed part of the composite without the tpad lead: ffmpeg then holds every earlier frame in memory (minutes for a clip late in the timeline).
- **Crop / flip / chroma key:** preview `MaskFxHost` = Host > crop box (opacity mask from `Crop.Fill` at the layer's size) > flip box (picture, mask effects, vignette); a cut-out mask on the Host is mirrored with the flip. Export order: scale → key (matte split off) → look → LUT → masks → vignette → flip → crop mask × key matte multiplied into the alpha (PGM / FFV1 mask from the same `Crop.Fill`) → blur (premultiplied first) → fades / opacity. The key runs in the preview's decoder (BGRA output, `FrameStream.Alpha`; graded on straight colours, then premultiplied into a Pbgra32 bitmap) and in the export at the clip's output size; the scrub cache can't show it. Keyed clips use the look decoders' start-up estimate and paused pre-roll.
- **Shape / move transitions:** Fx.Mask (clock wipe, barn doors, iris box / diamond, diagonal wipe, venetian blinds, inset): `Transitions.Shape(def, q)` is the preview's clip region (the outgoing shot stays whole when an opaque incoming one covers it) and, drawn by WPF at the output size, the export's FFV1 mask video: B's composite gets it as alpha and is overlaid on A's (4:2:0, no RGB round trip) inside trim / concat segments (`XFade`). Fx.Move (slides, cross zoom, zoom in / out, spin in / away): `XformOf` → `LookInfo` (offset, scale and turn about the frame centre, opacity, top) applied by `LookInfo.Apply` to clip placements (preview `Moved`, snapped like `LayerPlan.Box`) and to title motion; the export forces LayerPlan for such clips (`Transitions.Look` per frame — MaskExport must make the same choice), titles render per frame (`RenderSequence` with the plan), and Zoom Out / Spin Away composite B before A.
- **Audio effects:** one C# chain (`AudioDsp`) per clip, on its sound before volume / fades / pan, output rounded to 16-bit where the source is read. The playback mixer runs it live (`FxState`, warm-up after a jump; the mixer thread reads `Snapshot` copies — the inspector replaces lists when adding / removing); the export reads `fx_*.pcm` that `EnsureFile` rendered with the same chain from the clip's first sample (`RunAsync` first). `--audiotest` checks export = mixer (≥ 50 dB, it is ~86) and mid-clip start = played through. **Track effects** (`TrackMix.Fx`, in the mixer undo snapshot): the track's clips summed BEFORE its fader (sources get GL = GR = 1 and a `TrackBus`; `Mixer.Accumulate` is the one per-source sum), the chain on that float bus (unrounded; also where no clip sounds — reverb tails), then fader / pan / automation. Export: `EnsureTrackFile` renders the bus with the mixer's own code (`Mixer.PreFader` + `Chain.ProcessFloat`) from timeline 0 to f32le; the exporter skips that track's clips and reads the file (`pan` or the automation block after it) — `--audiotest` 83.7 dB, jump with reverb warm-up 61 dB.
- **Look effects / drop shadow:** sharpen, glow, grain are ffmpeg filters in `Looks.ColourGraph` after the drawn look — preview decoder and export (grain differs in pattern, not strength). Drop shadow: export `ShadowUnder` (the clip's alpha recoloured, padded, gblur, overlaid at an even offset under it); preview = a frame-sized rectangle with a `VisualBrush` of the layer as opacity mask (the brush includes the layer's offset and turn: its viewbox must be the frame), BlurEffect, offset.
- **Keys, mattes, pins:** luma key = `lumakey` with Level mapped to video black 16 … white 235. Track matte from a video / picture (`Clip.Mask` + `MatteLuma`): the clip isn't drawn; preview `WriteMatte` (0.299 R + 0.587 G + 0.114 B over black, or alpha; × crop; inverted for cut-out; pooled buffers) → `below[k]` opacity mask; export `TrackMatte` builds the same in RGB channels (colorchannelmixer → negate → fades over white → extractplanes) — never gray↔RGB conversions (range). Every alpha source (key matte, pin coverage, crop) is multiplied into the clip's alpha exactly once: the colour branch drops its alpha (`format=gbrp`) after a split (a kept key alpha was squared). Corner pin: the clip covers a frame-sized layer (`Placement` = full frame, decode at frame size); the export warps the picture with `Pin.Graph` (colours and alpha apart — perspective keeps no alpha), takes coverage as alpha and warps the key matte with `Pin.Warp`; keyframed corners (`Pin.Props`, by source time like every key) become per-frame `perspective` expressions of `in` (= frame k + 1 of the clip, `eval=frame`; straight runs as a + b·in in an `if(lt(in,…))` tree). The preview warps with `PinEffect` on the picture (and picture mask overlays) — the export's geometry exactly: on screen max 2 levels off ffmpeg. WPF puts a shader's pixel / texel centres at ½ on the GPU and at 0 in the software renderer (RenderTargetBitmap: every test and screenshot) → `Pin.Half` (App sets 0 for test commands and tier-0 PCs); a mirror transform above an effect is resampled by the software renderer, so flips are folded into the shader's matrix (`Pin.Mirror`, picture turned back inside the flip box). Track mattes keep the decoder warp with the base corners (`Pin.InDecoder`: their matte comes from decoder pixels). `--compositetest` measures the shader against perspective in both renderers (window + screen capture). Anchor point = pivot of scale and rotation in `Editor.Placement` (moving it doesn't move the clip).
- **Lens distortion:** export = ffmpeg `lenscorrection` (i=bilinear, fc=black@0) at the clip's output size, after the colour work, before the pin, on **gbrap with the alpha plane** (a grey plane's fill is 16); keyframes = sendcmd per frame; a key's matte rides in the alpha through the warp (multiplied once). Preview = the same model in `PinEffect`: source = ⌊cx·w⌋ centre + m·(s − centre) + ½ (lenscorrection's rounding constant lands in the fraction — a half-pixel shift that must be kept), m = 1 + k1·r² + k2·r⁴, r² = d²·4/(w²+h²), hard edge outside [0,w)×[0,h); lens-only clips: identity matrix on `Exporter.ClipSize`. `--compositetest` measures it on screen (≤ 1 level).
- **Source monitor:** the program's machinery, not a copy: a second `Preview` on its own one-clip `Editor` with a second `AudioOut` as its clock (the sequence's frame / rate statics apply: the clip is fitted into the sequence frame). Only one monitor plays (`Play` → `SrcPause`, `SrcPlay` → `Pause`); `SourceTick` does nothing while the panel is hidden. Marks live on the `MediaItem` (`SrcIn` / `SrcOut`, saved); every way onto the timeline (Insert / Overwrite, drags, Project panel) goes through `Editor.SourceRange`. Keys go to the source only while it was clicked last (`srcFocus`).
- **Composite format:** `ExportSettings.Full444` (default on; export dialog "Colour") = the composite is yuv444p / yuva444p (`P` / `PA` in `Exporter.Build`) and every overlay onto it names `:format=yuv444` (`OV` — ffmpeg's overlay defaults to yuv420 and would subsample each layer); the output is subsampled once at the end by `scale=flags=area,format=<OutPixFmt>`, and same-size clips are converted the way the preview's decoder converts them (`Chroma(c)`: plain clips `flags=neighbor` = swscale's unscaled yuv→BGR, which repeats chroma; clips whose decoder runs a graph — key, looks, warp — `bilinear` like `Decoders.Filter`; pictures `bilinear` like Windows' decoder). Repetition + area average = a 4:2:0 source's chroma back exactly (bicubic both ways cost the captions test 1–2 dB). Positions keep the 4:2:0 overlay's even grid (`Ex` / `Ei`: `(int)x & ~1`, which the preview places on). Off = the old 4:2:0 composite. New composite steps must use `P` / `PA` / `OV`, never literal yuv420p. Nested renders follow it (FFV1 yuva444p; `Nest.Version` n4). `--compositetest` measures it: mean preview-vs-export 33.2 dB (4:2:0 composite) → 33.5 (4:4:4, H.264 4:2:0 out) → 37.7 (ProRes 4444 master), export ~13 % slower.
- **Static placement:** a 4:2:0 overlay can only place on even pixels (kept with the 4:4:4 composite: the 4:2:0 option and H.264 output share the grid), so static clips export at the nearest even output pixel and `Editor.Placement` snaps them to the same grid in the preview (an odd or fractional position used to be off by up to a pixel).
- **Sequences:** a project holds several (`Editor.Sequences`); the editor edits one (`Seq`): `Clips`, `Mix`, `TrackOff`, `Time`, In / Out forward to it, its format lives in the statics (`SetSequence`; `FormatOf` / `CaptureFormat` for the others / saving). Preview and export read the same file: a nested clip is a video clip with alpha (keyed-clip path: alpha split off and multiplied once, premultiplied scaling on both sides); `Nest.FrameAt` is the one frame rule (start frame by number, then the export's fps filter rule) — the preview decodes that frame on the render's own grid. Nested clips play at 100 % (no speed / holds). `--nesttest` checks transparent render = normal export, Nest = un-nested, preview = export.
- **Adjustment layers** (`ClipKind.Adjustment`, any video track above V1): one rule at strength s (opacity × fades): blur radius·s → colour s of the way through the grade → vignette at s (`Adjust`). Preview: `below[k]` carries the `LutEffect` and is nearest-neighbour while it does (WPF stretches an effect's brush input to the element with the element's scaling mode, and its lookups land half a texel off — so the LUT is a small 17³ texture whose entries span several pixels, and the shader interpolates itself); the blur is on `adjIn[k]`, the vignette on `adjVig[k]` above. Auto-save never runs in automated runs (`AppSettings.ReadOnly`); its files are written to a .tmp and moved.
- **Dockable panels:** (a WPF tooltip outliving a floating window — the panel docked back under the mouse — throws Win32 1400 from PopupControlService on the next mouse move; App's dispatcher handler ignores exactly that.) Panels are the same elements wherever they are — `MoveDock` re-parents them (left / right / bottom hosts, a `DockWindow`), so features keep their x:Name references; anything that runs only while a panel shows tests `Shows(el)` (visible with a size), never which side bar is open. Effect Controls resolve their ink from the card they're in (`inkScope = CardOf(InspectorView)`); a floating panel gets its own `Card` with its home region's palette. Floating windows are owned by the main window, so they can't be created before it is shown (a saved layout floats them on `Loaded`); closing one docks it back; the main window's Closing sets them `Quiet` and saves the layout. Automated runs use the Editing workspace (or `CUTPRO_WORKSPACE`), never the saved layout. Full screen moves `MonitorBox` (Pv + overlays) into a borderless window and back. `--docktest`; the `float` playtest measures a floating monitor (same frame gap as docked).
- Window uses `WindowChrome` (custom title bar): title-bar controls need `WindowChrome.IsHitTestVisibleInChrome` (set in the Button styles). Sashes overlay panel edges (no layout column).

## Environment gotchas
- Windows 11, PowerShell 5.1 + Git Bash. **No python, no node.** Use `sed`, the Edit tool, or write snippets with the Write tool (bash heredocs containing `'` sometimes fail in this harness).
- sed replacement text: `\U`/`\L` change case (bit us on `C:\Users`) and `\n` becomes a newline even inside C# strings — use the Edit tool for such lines.
- `Start-Process -ArgumentList` does not quote arguments with spaces: pass `'"Light Theme"'`. If the user has CutPro open, don't kill it (unsaved work): build to `dotnet build -c Release CutPro -o %TEMP%\cutpro_dev` and test that exe; `test.ps1` kills CutPro, so run it only when the app is closed.
- `ImplicitUsings` doesn't apply in this WPF project → `GlobalUsings.cs` exists; add namespaces there.
- ffmpeg 7+ removed `-filter_complex_script`; filter chains must be `;`-joined.
- PowerShell regex: escape backslashes (`'\\CutPro\\'`).

## Effort auto-adjust (the user asked for this)
Pick the effort for each piece of work from this table instead of using one level for everything:

| Level | Use for |
|---|---|
| `low` | docs / PROGRESS / Handoff updates, renames, UI text, running tests, one-line fixes whose cause is already known |
| `medium` | XAML layout, styles, menu items / commands / settings fields, palette keys, new test scenarios built on existing ones |
| `high` (default) | a new feature inside one area (timeline drawing, inspector, a dialog), bug fixes with a reproduction |
| `xhigh` | anything with **preview ↔ export parity** (`Exporter`, `LayerPlan`, `MaskExport`, `Transitions`, audio mixing / loudness), playback and frame-time work (`Preview`, `FrameStream`, `AudioOut`, `OnRendering`, `Ambience`), threading, the undo model, the project file format |
| `max` | the same failure after two fix attempts, A/V sync or freeze bugs, a parity test that won't converge, designing a subsystem that spans more than 4 files |

How to apply it:
1. **At the start of each request:** read the session's effort (desktop app: `mcp__ccd_session_mgmt__get_session` with `"self"` → `effort`). Classify the request by its hardest part.
   - If that part needs a higher level, say so in one line ("this touches export parity — xhigh recommended") and carry on. The user changes it in the app's effort control.
   - If the whole request is `low`/`medium` work while the session is at `xhigh`/`max`, suggest lowering it to save usage.
   - A session can't change its own effort: `set_session_effort` refuses the current session. Never block on the answer.
2. **Within a turn**, the session's level is the ceiling; spend reasoning by the table. Mechanical steps (docs, test runs, boilerplate) go quickly. Parity and performance steps get the full treatment: design first, then a test that measures it.
3. **Escalate:** after two failed fixes for the same failure, stop patching. Re-read the design rules above and recommend `max` before the third attempt.
4. **Subagents** (only when the user asks for them): pass `effort` from the table to the `Agent` tool for the delegated part.
